Problem Understanding
Regulatory Context: EIA Screening in India
Why pre-screening precision is critical prior to environmental impact appraisal
The Statutory Mandate
  • Before an industrial project begins in India, prior environmental clearance is required under EIA 2006.
  • Screening determines: Is the project in the Schedule? Is it Category A or Category B?
  • Decided before any assessment begins.
High Cost of Error
  • Category A is appraised centrally by MoEFCC on EAC recommendation.
  • Category B is appraised by State SEIAA.
  • A clearance granted at the wrong level can be set aside by the National Green Tribunal, halting construction.
System Philosophy
  • This is a production service, not a notebook.
  • Never determines clearance authoritatively; produces a screening opinion.
  • All decisions grounded in retrieved provisions. Accredited consultant makes the final decision.

Core Technical Challenge
The Difficult Case (§4.1) & Retrieval Traps
Why naive semantic RAG fails and multi-agent reasoning is essential
The Demonstration Scenario
  • Input: Industrial cement plant of 0.8 MTPA capacity, located 2.0 km from a National Park boundary.
  • The Naive RAG Trap: A single retrieval pass returns Schedule Item 3(b) (which places capacity < 1.0 MTPA in Category B).
  • The Failure: Reporting Category B alone fails the demonstration because the project modifies under sensitive proximity!
The Multi-Agent Solution
  • General Condition (GC): Printed in a note after the Schedule, shifts Cat B projects within 5 km of Protected Areas to Category A.
  • Explicit Modifier Retrieval: Screener identifies Schedule 3(b) and invokes find_modifiers to retrieve the General Condition.
  • Dual Grounded Citation: Final recommendation cites BOTH Schedule Item 3(b) and General Condition S.O. 1599(E).

System Architecture
Multi-Agent Reasoning Topology (A1–A3)
Built with LangGraph with distinct responsibilities and defined hand-offs
1. Extractor Node
  • Parses structured and narrative descriptions.
  • L4 Guardrail: Prompt injection defense on all free-text fields.
  • Extracts capacity, location, and sensitive feature proximity entities.
  • Flags missing or uncertain fields.
2. Screener Node
  • Matches sector against statutory Schedule thresholds.
  • Dynamic Tools: Calls search_corpus, get_clause, and find_modifiers.
  • Applies General Condition S.O. 1599(E) 5 km / 10 km rules.
  • Evaluates F7 escalation boundaries.
3. Verifier Node
  • Requirement A3: Every citation must resolve to text retrieved during the run.
  • Category A via GC must cite BOTH Schedule and General Condition.
  • Checks Category/Route consistency.
  • Bounded execution: max 10 steps, 8 tool calls, 2 retries.

05 / 12
Platform Engineering
Ingestion Boundary & Quarantine Isolation (D1 / F2)
Strict validation preventing malformed requests from launching agent runs
Published Data Contract
  • POST /v1/screenings enforced with strict Pydantic contract.
  • Schema, range, categorical, and cross-field validation at boundary.
  • Rejects negative capacity (e.g. -5 MTPA), negative distances, and unit mismatches (MW for cement).
  • Returns HTTP 422 Unprocessable Entity with field errors.
Quarantine Architecture (Demo Item 4)
  • Malformed payloads are quarantined to quarantined_records.json.
  • Guaranteed: Zero agent runs started on invalid input.
  • Auditable via GET /v1/quarantine.
  • Async polling pattern: Valid requests return HTTP 202 Accepted + /v1/screenings/{id}.

Reliability & Safety
Knowing When NOT to Answer (Requirement F7)
Escalating to human review when evidence is uncertain or conflicting
1. Proximity Uncertain (RC-8)
  • Protected area identified but distance omitted or approximate.
  • When estimated proximity falls within ±1 km margin of 5 km threshold (4.0–6.0 km).
  • Outcome: ESCALATE_TO_HUMAN (PROXIMITY_UNCERTAIN).
2. Amendment Conflict (RC-7)
  • Building & Construction Item 8(a) projects.
  • S.O. 3999(E) was quashed by National Green Tribunal (Footnote 92 in consolidated text).
  • Outcome: ESCALATE_TO_HUMAN (AMENDMENT_CONFLICT).
3. Outside Corpus (RC-9)
  • Projects falling under Coastal Regulation Zone (CRZ Notification 2019/2011).
  • Appraised by NCZMA/SCZMA, outside EIA 2006 Schedule.
  • Outcome: ESCALATE_TO_HUMAN (OUT_OF_CORPUS).

Deployment & Operations
Docker Compose Architecture & Scaling (D3 / A7)
Five containerized services running from a clean clone with horizontal scaling
1. API & Worker Tier
  • eia-api: FastAPI ingestion boundary and web UI client on port 8000.
  • agent-worker: Scalable asynchronous task processor.
  • Horizontal Worker Scaling (A7): docker compose up --scale agent-worker=3.
2. Queue & Caching Tier
  • eia-redis: Redis 7 on port 6379.
  • Decoupled queue: submissions never block HTTP requests.
  • Run Caching (D7): identical payloads served instantly with zero model calls.
  • Client rate limiting (60 req/min).
3. Observability Tier
  • eia-prometheus: Scrapes metrics every 5s on port 9090.
  • eia-jaeger: Distributed tracing UI on port 16686.
  • Single command: docker compose up -d.
  • Zero secrets in repo (.env.example).
